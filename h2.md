
# Plan: Extract h2 protocol logic into a standalone `h2-core` crate

## Context

You're building a new runtime and need HTTP/2 protocol support. The h2 crate bundles pure protocol logic (frame parsing, HPACK, stream state machines, flow control) together with tokio-specific IO/codec code. The goal is to extract the IO-agnostic protocol logic into a separate `h2-core` crate so you can plug in your own IO/codec layer.

## Architecture: What goes where

### `h2-core` (new crate — pure protocol logic, no tokio)
- `frame/*` — frame types, encoding/decoding
- `hpack/*` — header compression
- `proto/*` — connection state machine, stream management, flow control, prioritization
- `error.rs` — error types
- `ext.rs` — extension traits
- A new **`FrameCodec` trait** defining the interface the proto layer needs

### `h2` (existing crate — becomes a thin wrapper)
- `codec/*` — tokio-based `FramedRead`/`FramedWrite` (implements `FrameCodec`)
- `client.rs`, `server.rs`, `share.rs` — user-facing async API
- Depends on `h2-core`

### Your new crate
- Implements `FrameCodec` for your runtime
- Depends on `h2-core`
- Provides its own client/server API

## Key change: The `FrameCodec` trait

The proto layer currently calls these methods on the concrete `Codec<T, B>`:

```rust
pub trait FrameCodec<B: Buf> {
    // Reading frames (replaces Stream impl)
    fn poll_next(self: Pin<&mut Self>, cx: &mut Context) -> Poll<Option<Result<Frame, Error>>>;

    // Writing frames
    fn poll_ready(&mut self, cx: &mut Context) -> Poll<io::Result<()>>;
    fn buffer(&mut self, item: Frame<B>) -> Result<(), UserError>;
    fn flush(&mut self, cx: &mut Context) -> Poll<io::Result<()>>;
    fn shutdown(&mut self, cx: &mut Context) -> Poll<io::Result<()>>;

    // Settings configuration
    fn set_max_recv_frame_size(&mut self, val: usize);
    fn set_max_send_frame_size(&mut self, val: usize);
    fn set_send_header_table_size(&mut self, val: usize);
    fn set_recv_header_table_size(&mut self, val: usize);
    fn set_max_recv_header_list_size(&mut self, val: usize);
    fn max_send_frame_size(&self) -> usize;

    // Data frame reclamation (used by prioritizer)
    fn take_last_data_frame(&mut self) -> Option<Data<B>>;
}
```

## Step-by-step implementation

### Step 1: Create `h2-core` crate skeleton
- Create `h2-core/` directory alongside `h2/` (or as a workspace member)
- Set up `Cargo.toml` with minimal deps: `bytes`, `http`, `fnv`, `slab`, `indexmap`, `tracing`, `atomic-waker`
- **No** `tokio` or `tokio-util` dependency

### Step 2: Move pure-logic modules into `h2-core`
- Copy `frame/`, `hpack/`, `error.rs`, `ext.rs` as-is (these have zero IO deps)
- Copy `proto/` including `proto/streams/*`

### Step 3: Define the `FrameCodec` trait in `h2-core`
- Place in `h2-core/src/codec_trait.rs` (or similar)
- This replaces all concrete `Codec<T, B>` references in the proto layer

### Step 4: Refactor proto to be generic over `FrameCodec`
Key files to modify:
- **`proto/connection.rs`**: Change `codec: Codec<T, Prioritized<B>>` → generic `C: FrameCodec<Prioritized<B>>`
- **`proto/streams/prioritize.rs`**: Change `dst: &mut Codec<T, Prioritized<B>>` → `dst: &mut C` where `C: FrameCodec<...>`
- **`proto/settings.rs`**: Same pattern — replace concrete Codec with trait
- **`proto/ping_pong.rs`**: Same
- **`proto/go_away.rs`**: Same
- Remove the `T: AsyncRead + AsyncWrite` bounds from proto types (they move to the codec impl)

### Step 5: Update `h2` crate to depend on `h2-core`
- Add `h2-core` as dependency
- Implement `FrameCodec` for the existing `Codec<T, B>` type
- Re-export `h2-core` types from `h2`'s public API
- `client.rs`, `server.rs`, `share.rs` use `h2-core`'s proto with the tokio Codec

### Step 6: Verify
- `cargo build` on both crates
- Run existing h2 test suite — nothing should break
- Verify `h2-core` compiles without tokio
